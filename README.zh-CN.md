# AgentDemo

[English](README.md) | [简体中文](README.zh-CN.md)

一个本地优先的 AI 工作台，支持日常对话、编程、资料检索和创作。接入你自己的模型服务，在同一界面中使用项目文件、技能、知识库和多 Agent 协作。

基于 **TypeScript、Node.js、React、Fastify 和 SQLite**。界面支持中英文切换、字号调整和自定义助手名称。

## 主要功能

- **对话与项目**：普通对话、多文件夹项目、附件、技能搜索、对话分支和代码复制。
- **模型接入**：支持 OpenAI-compatible Chat Completions、OpenAI Responses、Anthropic Messages 和 Gemini 协议，提供模型发现及模型支持的推理等级设置。
- **实时进度**：流式回复、可折叠执行步骤、任务进度、文件修改对比、API 用量和上下文压缩详情。
- **工具与团队**：文件编辑、命令执行、网页搜索与抓取、图片读取、后台任务和带独立可写副本的 Agent 协作。
- **知识与记忆**：按范围检索文档、可选 embedding，以及从已开启的对话中后台提取记忆。
- **媒体与语音**：可配置图片、视频、音乐、3D、转录和语音合成服务；录音转文字后先放入输入框供编辑。
- **权限控制**：只读、人工审批、辅助审批，以及宿主、AppContainer 和 Docker 执行后端。
- **本地持久化**：保存对话、任务状态和操作记录；服务重启后不会静默重放结果不明的操作。

## 快速开始

### 环境要求

- **Node.js 24 或更新版本**
- **pnpm**，或能够运行 pnpm 的 Corepack
- 你准备使用的模型 API 连接

部分依赖包含原生模块。如果安装时报原生模块构建失败，需要先安装当前平台对应的编译工具再重试。

### 安装与启动

```sh
git clone https://github.com/renjie22122-maker/AgentDemo.git
cd AgentDemo
corepack pnpm install
corepack pnpm build
corepack pnpm start
```

如果环境中没有 Corepack，安装 pnpm 后，将命令中的 `corepack pnpm` 替换为 `pnpm`。

打开 **http://127.0.0.1:8810**，进入**设置**添加模型连接，填写服务地址和 API 密钥，再测试连接。

Windows 用户安装依赖后，也可以双击 **Start-AgentDemo.cmd**。启动器会启动本地守护进程并打开浏览器。它使用的 PowerShell 执行策略覆盖仅对启动进程生效，不修改系统策略。

## 日常使用

1. **选择普通对话或项目。** 普通对话独立保存附件与产物；需要操作本地文件夹时，创建项目并添加一个或多个目录。
2. **选择模型与权限。** 在输入框附近调整推理等级、协作方式和执行权限。可用推理等级取决于模型。
3. **提供资料。** 拖入附件、选择技能，或把文档加入知识库。
4. **发送任务。** 查看执行进度和文件修改，在对话中回答问题或审批操作；执行期间也可以追加消息。
5. **查看结果。** 按需展开工具输出和文件差异。操作中断时，先核对记录的结果，再决定是否重试。

普通对话不能执行项目命令。需要运行本地命令时，请先选择项目。

### 管理工作区

点击左侧项目旁的 **…**，可以改名、追加或移除文件夹，包括不同磁盘或不同位置的目录。Windows 下点击“用 Windows Explorer 选择文件夹”打开现代系统选择器，支持 Ctrl/Shift 多选；不同位置可分次追加，也可以每行粘贴一个绝对路径。支持最多 12 个互不重叠的目录。

**Remove Project / 移除项目**会停用工作区，不删除磁盘文件、历史对话、知识库或记忆。可以在侧栏归档视图中找到已移除项目，保存设置即可恢复，项目记忆范围保持独立。修改目录或移除前需先停止该项目的运行任务。

### 彻底删除对话

在对话菜单选择“彻底删除对话”，再输入完整标题进行二次确认。删除消息、子 Agent、运行记录及专属本地附件/产物；独立分支、已保存记忆和项目文件保留。运行任务和后台操作需先停止。删除后无法在应用内恢复，但不代表安全擦除备份或 SQLite 空闲页中的历史字节。

### 技能

在技能库导入技能目录，按来源、分类或关键词筛选，支持批量选择和取消。可选的 AI 分类会先展示预览，由你决定是否应用。

Agent 可以发现已启用技能，并将配套脚本或资源复制到任务工作目录。导入技能不会自动安装依赖，也不会自动授予执行权限。

### 知识库与记忆

**知识库**用于手册、规范、数据集等来源文档，按配置的项目或对话范围检索。Embedding 索引是可选项，建立索引和查询时会向配置的 embedding 服务发送相应文本。

**记忆**用于长期偏好和决策。对话详情中，“使用已有记忆”和“允许此对话生成未来记忆”是两个独立开关：

| 对话类型   | 新记忆保存到   | 默认召回     |
| ---------- | -------------- | ------------ |
| 普通对话   | 共享的用户记忆 | 用户记忆     |
| 项目内对话 | 当前项目记忆   | 当前项目记忆 |

项目可以显式开启召回用户记忆。不同项目之间不共享项目记忆，普通对话也不读取项目记忆。

对话开启记忆生成后，空闲时会将最多 30 条近期用户消息和 80 条同范围记忆发送给该对话配置的模型服务。明确且无冲突的偏好可自动生效，决策和冲突内容等待确认。可以在记忆页查看、删除条目。详见[记忆控制与数据流程](docs/MEMORY.md)。

记忆管理还支持有效时间、人工冲突替代、修订历史、来源级遗忘和带验证证据的经验。
工作台可管理已确认实体别名与有来源的关系，按指定时间检索最多三跳路径。
知识库支持导入新版本，返回版本化引用与相邻段落。详见[记忆与证据图谱](docs/MEMORY.md)。

### 媒体服务

媒体服务与聊天模型分别配置。适配器包括 OpenAI-compatible 服务、fal.ai、Replicate、Gemini、ElevenLabs、Deepgram、AssemblyAI、Meshy、Tripo 和 MiniMax。

具体能力取决于所选模型和服务账号，需要填写真实模型 ID 及必要参数。支持协议不代表已实测所有模型。生成调用可能单独计费，界面估价不是服务商账单。当前语音输入是录音结束后上传转文字，不是实时语音通话。

## 执行环境与审批

隔离方式和审批方式分别设置：审批决定能否启动操作，执行后端决定操作系统层面的访问边界。

| 执行后端                | 行为                                       | 额外要求                           |
| ----------------------- | ------------------------------------------ | ---------------------------------- |
| 宿主审批                | 使用宿主用户权限执行命令                   | 无额外运行时                       |
| AppContainer · 文件隔离 | Windows 文件隔离，允许网络访问             | Windows 及配置好的 Python 绝对路径 |
| AppContainer · 严格离线 | 文件隔离并预检断网能力，预检失败则拒绝执行 | Windows 及配置好的 Python 绝对路径 |
| Docker · 离线容器       | 容器内执行，禁用网络                       | Docker 及已准备好的镜像            |

**项目文件夹不等于沙箱。** 获批的宿主命令可能访问项目外的文件和网络。“帮我审批”通过独立模型请求审核操作，必要时转人工；它不改变隔离范围，也不保证识别全部风险。

详见[安全说明](docs/SECURITY.md)和[执行后端说明](docs/MIGRATION.md)。

## 本地数据

对话、设置和运行记录保存在本机。调用外部模型、embedding、搜索或媒体服务时，会把相应操作需要的输入发送给配置的服务。

- `.data/`：应用私有状态，不进入 Git。
- `.diagnostics/`：本地诊断及测试产物，不进入 Git。
- Windows 使用当前用户的 DPAPI 保护 API 密钥；其他平台使用受文件权限限制的本地文件。
- 请保留导入技能的来源目录。

迁移安装前备份私有数据。分享仓库时不要包含这些数据。

在两个终端分别运行：

```sh
corepack pnpm dev
corepack pnpm web
```

后端端口为 **8810**，Vite 前端端口为 **8811**，并代理 API 请求。

corepack pnpm check
corepack pnpm test

## 常见问题

- **模型连接测试失败**：检查设置中的端点、密钥、代理及模型 ID。
- **命令无法启动**：查看执行后端和预检结果。AppContainer 需要 Python 路径；Docker 需要运行中的引擎和已准备好的镜像。
- **技能不可用**：检查技能依赖的工具、包、账号和网络权限。导入不会自动准备执行环境。
- **操作中断**：重试写入或命令前先确认结果。重启应用不能证明外部操作是否已经完成。
- **Windows 启动器失败**：检查 `.data/logs/`，确认 Node.js 24+ 和依赖已安装。

提交问题时，请提供操作系统、Node 版本、执行后端、复现步骤和脱敏后的报错。不要附带密钥或私有聊天数据。

### 执行与恢复设置

新安装默认选择 Windows AppContainer（其他平台为 Docker），已有配置不自动切换。宿主执行必须显式选择，它不提供 OS 文件隔离。Ask 默认审批命令；设置中的“文件写入也需要审批”可额外覆盖文件工具，Trusted 模式除外。

当前 Windows 原生后端遇到 `.git` / `.agentdemo` 会在启动前拒绝命令：选择性元数据 ACL 未通过实测，请使用不含元数据的隔离副本。Docker 默认非 root 用户，并屏蔽元数据目录；本机尚未完成 Docker 集成验证。

可恢复中断有明确原因；不确定操作可通过用户确认核实结果，不会自动重放。命令成功和文件覆盖分别记录，不能把退出码 0 当成全部产物正确。

### Windows 首次启动

先安装 **Node.js 24 或更新版本（包含 npm）**，完整解压仓库后双击 **First-Start-AgentDemo.cmd**。它会安装锁定版本的项目依赖、构建界面并启动浏览器，无需自己安装 Corepack 或全局 pnpm。首次安装需要联网；如果原生模块编译失败，按提示补齐 Python 和 Visual Studio C++ Build Tools 后重试。重复运行不会清空聊天或配置。

以后双击 **Start-AgentDemo.cmd** 即可；它发现缺少依赖时也会自动进入初始化。尚未安装 Node.js 时，启动器会显示官方下载地址和安装命令，不会静默修改系统环境。
